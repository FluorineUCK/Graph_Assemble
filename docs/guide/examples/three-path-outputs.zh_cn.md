# 一张图，三种路径产物，三组失败品池

[English](three-path-outputs.md) | 简体中文

脚本：[kubejs/three_path_outputs.js](../../../examples/kubejs/three_path_outputs.js)。配方 ID：`example:three_path_outputs`。

这是 **一张图、一个原料入口、三个严格结算出口**示例。示例故意使用容易识别的原版物品演示规则，不是平衡过的生产配方。需要 Graph Assembly、Create 与 KubeJS。

## 安装

1. 把脚本复制到实例的 `kubejs/server_scripts/three_path_outputs.js`。
2. 执行 `/reload`，确认没有脚本错误；管理员可执行 `/graph_assembly compatibility` 检查图是否可执行。
3. 使用新的 **粗铁 `minecraft:raw_iron`**。不要给工件手写进度。其他自定义图如果也采用粗铁＋冲压入口，应避免同时启用。


## 实际路线

先把一份粗铁在置物台／传送带上冲压一次，经过 `blank` 得到带图进度的铁粒工件。之后选择下面任意一条路线：

| 路线 | 工序与附加消耗 | 成功次数范围 | 结算工序 | 成功产物 |
|---|---|---|---|---|
| 切割 | 动力锯，每次 40 tick 的配方处理时间 | `cut` 1～2 次 | 再冲压一次，进入 `finish_iron` | 铁锭 ×1 |
| 装配 | 机械手，每次消耗红石 ×1 | `wire` 2～3 次 | 再冲压一次，进入 `finish_gold` | 金锭 ×1 |
| 注液 | 注液器，每次消耗水 250 mB | `fill` 恰好 1 次 | 再冲压一次，进入 `finish_diamond` | 钻石 ×1 |

加工次数包含第一次进入该节点，不是额外循环次数。自环允许继续加工，最终冲压才结算。不要把最后冲压改成工作盆压缩：此例使用的是 `create:pressing`。

```text
粗铁 → blank（冲压）
          ├─ cut  ↺（切割 1～2 次）──→ finish_iron    → 铁锭
          ├─ wire ↺（机械手 2～3 次）→ finish_gold    → 金锭
          └─ fill ↺（注水 1 次）─────→ finish_diamond → 钻石
```

分支由玩家送往哪种设备决定，全部使用默认 `choice`，没有随机选择路线。进入一条路线后，只能循环该工序或到对应出口；没有跨路线连接。

每次路线工序增加 `quality: 1`，并记录 checkpoint。出口同时检查：

- 必须按顺序经过 `blank → 对应工序 → 对应 finish`（`partial` 有序子序列，允许合法重复）；
- `quality` 位于该路线的 `mark_ranges`；
- 对应 checkpoint 的累计次数位于 `checkpoint_counts`。

范围包含两端，条件为 AND。

## 对应失败品池

| 出口 | 可复现的失败路径 | 只从本出口抽取的失败品池 |
|---|---|---|
| `finish_iron` | 切割 3 次或更多，然后冲压 | 铁粒 ×3：权重 3（75%）；沙砾 ×1：权重 1（25%） |
| `finish_gold` | 机械手只加工 1 次，或加工 4 次以上，然后冲压 | 金粒 ×2：权重 2（2/3）；红石 ×1：权重 1（1/3） |
| `finish_diamond` | 注水 2 次以上，然后冲压 | 石英 ×1：权重 1（25%）；燧石 ×2：权重 3（75%） |

**这些比例是在已经失败的前提下抽哪个废品，不是成功率。** 合格路径必定获得对应成功物品；不合格路径到达该严格出口时必定失败，再从该出口的池中抽取一次。不是把两个废品一起发放。

严格失败会结束图进度。即使失败得到的铁粒外观与中间工件相同，它也只是普通铁粒，不继续携带图进度。成功产物同样不携带进度。

没有合法边的操作属于停工，不是结算失败。例如 `blank` 后立即再冲压没有合法后继，机器不能凭空选择三个出口之一；`cut` 后也不能直接跳到 `finish_gold`。不要把“停工”误认为应当抽废品。

### 为什么用三个 finish

现有 `scrap` 属于 finish 节点，而不是成功规则。用三个严格出口就能自然表达三组对应失败池，三个出口都可使用冲压，因为工件当前所在分支只允许其中一个，不会产生三个同条件候选。

成功规则写在各 finish 的 `outputs`，图级 `outputs` 保持空数组。不要在图级加无条件成功规则：它会与节点规则共同参与结算，让本应失败的工件也得到成功产物，从而绕过废品池。

如果以后要求“同一个 finish，根据失败路径再选择不同 scrap”，那是另一项条件废品规则需求；本示例没有假装现有格式支持它。

## JEI 出口联动显示

- 查询三种成功产物或六种失败品，均可关联到这一张图；选择出口不会改变 JEI 的完整索引。
- 默认“全部出口”同时展示三种成功候选，不是同时发放三件产物，也不是预测当前工件的成功概率。
- 右下出口选择器或图中 finish 节点可以切换出口；底部成功候选与失败池同步切换。例如金出口只显示金锭，以及金粒／红石，不会混入石英。
- 候选较多时点击 `+N` 展开；出口列表可以滚动，候选层可以翻页。真实物品槽保留 JEI 配方／用途操作，导航按钮不充当物品槽。
- Esc 先关闭展开层；切换出口不重置图的缩放、平移或球面方向。
- 原生 Info 页仍按出口列出完整成功条件和失败池。页脚只显示候选和摘要，不把所有可能规则合成一条条件或一个固定概率。
- 入口是入口原料候选，不是完整材料清单；辅助工件、红石和水等仍在对应节点预览／详情中查看。
- 新页脚复用现有 PNG／Create 原生按钮，不覆盖人工图集。图的交叉连线和模型裁切是独立布局问题。

## 最小验证清单

- [ ] `blank → cut → finish_iron` 与切割两次均得到铁锭。
- [ ] `blank → wire → wire → finish_gold` 与机械手三次均得到金锭。
- [ ] `blank → fill → finish_diamond` 得到钻石。
- [ ] 切割三次、机械手一次／四次、注水两次分别只进入自己的失败池。
- [ ] 成功及失败产物都没有图进度，正常物品数量与表格相符。

按清单逐条验证三条成功路线与对应失败品池。
