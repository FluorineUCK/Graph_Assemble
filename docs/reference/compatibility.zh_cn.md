# 执行兼容性参考

[English](compatibility.md) | 简体中文

本页列出图节点可以使用的设备、配方类型和交付规则。附属配方沿用受支持的原生类型时适用相同规则；附属自定义机器需单独适配。JEI 预览复用原生布局，范围可以大于实际执行支持。

## 图执行

| 配方类型 | 执行范围 |
|---|---|
| `create:pressing` | 动力冲压机；无辅助输入，最多 1 项副产物 |
| `create:cutting` | 动力锯；无辅助输入，最多 3 项副产物；`processing_time` 由原生 codec 解码，没有额外正数约束 |
| `create:deploying` | 机械手；恰有 1 个辅助物品输入，最多 3 项副产物；支持 `keep_held_item` |
| `create:filling` | 注液；恰有 1 个流体输入，不能有副产物 |
| `create:milling` | 石磨；无辅助输入，最多 3 项副产物，且 `processing_time > 0` |
| `create:mixing` | 工作盆搅拌；最多 63 个辅助物品、2 个辅助流体、3 项副产物；物品输入总数最多 64、输出最多 4，保留热量要求 |
| `create:compacting` | 工作盆压缩；最多 63 个辅助物品、2 个辅助流体、3 项副产物；物品输入总数最多 64、输出最多 4，保留热量要求 |

表中辅助输入与副产物上限已扣除一个主输入／主输出。简写模式自动补入主工件；完整模板使用原有物品输入 0／输出 0，均通过同一原生 codec 和设备校验。动力锯按最坏批量输出预留空间；容量不足时保留输入，不加工。石磨空间不足时保留输入等待空槽。所有执行适配均不接受原生流体输出。完整字段与限制见[配方格式](recipe-format.zh_cn.md)及[KubeJS 指南](../guide/kubejs.zh_cn.md)。

### 原版合成

`minecraft:crafting_shaped`、`minecraft:crafting_shapeless` 支持原生背包 2×2 和工作台 3×3 菜单。保留图案、镜像、材料条件与返还物规则；多工件分别校验，产物只继承主工件进度。配方使用完整原生 JSON 或引用，不套用 Create 的辅助输入简写。

点击时重新校验，空间不足不消费、不抽签。左右键取出一整轮：第一堆到鼠标，其余到背包；Shift 连续合成，每轮重新检查。数字键／副手换位仅接受空目标槽。图预览不能用中键复制或 Q 键直接丢出；先取到背包后可正常操作。

除下述染色与修理外，其他特殊合成及第三方合成菜单尚未开放图执行。相同 serializer 不代表自定义配方子类也受支持。

### 原版染色与修理

确切原生 `ArmorDyeRecipe`、`RepairItemRecipe` 支持背包、工作台及原版合成器。染色被染物是唯一主工件，染料按从左到右、从上到下的格位顺序作为辅助输入；修理第一非空格为主件、第二格为辅件，分别校验且只继承主件进度。非 finish 使用原生结果载体，finish 按图结算；节点级 `transitional_item` 不允许。Create 特殊图步骤、其他特殊合成未开放。

### 原版酿造台

`graph_assembly:brewing` 支持两种主件模式：各瓶保留各自进度，或共用材料向所有合法瓶子分发进度。每瓶独立推进与结算，共用材料只扣一次；带进度辅件须明确声明并分别校验。

实际效果查询原生 `PotionBrewing`，保留药水组件、燃料、时长、事件与材料余物。每个瓶槽仅接受空图结果或一件产物，整轮校验后提交。普通酿造仍执行原始调用链；图工件不能退回普通加工。

只接入确切原版 `BrewingStandBlockEntity` 和酿造台方块。注册到原生查询中的规则无需按模组名称区分；这不自动开放自定义机器、Create 流体酿造或附属酿造台子类。格式见[酿造台操作](recipe-format.zh_cn.md#酿造台操作)。

### 原版铁砧

`graph_assembly:anvil` 支持修理、附魔增强、显式改名和宿主已有的合法双输入组合。左槽主件、右槽辅件分别校验，仅继承左件进度；结果、费用与扣料沿用完整原生操作。中间步骤保留原生结果，finish 仅交付图结算产物。

铁砧适配接入原版 `AnvilMenu` 的计算和取出流程，也接受上游扩展在该流程返回的合法结果。AnvilCraft 独立二／四／八合一菜单、皇家铁砧及世界落砧配方不在此范围。

### 原版合成器

原版合成器共用上述标准有序／无序配方格式、主辅工件校验和图预览。每次红石上升沿加工一轮，执行时重新绑定输入与当前配方；禁用槽和漏斗分配沿用原版。

产物与原生返还物从前方送入容器，放不下的部分按原版弹出；返还物不回填输入网格。保留普通无图配方。除上述染色与修理外，其他特殊合成、自定义配方子类及附属合成器不自动获得该适配。

### 原版熔炉族

| 配方类型 | 原版设备 |
|---|---|
| `minecraft:smelting` | 熔炉 |
| `minecraft:smoking` | 烟熏炉 |
| `minecraft:blasting` | 高炉 |

使用完整原生配方或引用。只有一个主工件输入；燃料不计作辅件。每种可能产物组合须能完整放入单个输出槽，同一轮多种物品无法合并时停工，不截断、不丢弃。燃料时长、冷却和余物沿用原版规则，成功轮次的经验支持取出与拆除领取。

只接入上述原版设备与确切标准配方类，附属自定义炉子未开放。

### 原版营火

`minecraft:campfire_cooking` 支持原版营火与灵魂营火，复用烹饪查询和图结算。节点条件 `campfire` 可限定 `normal` 或 `soul`，省略或 `any` 时两者均可；放料与加工均按当前火种检查，不改普通营火配方。四格各自计时、各自加工一件主工件；不是多输入合并。保留原生放料、熄灭降温与掉落方式，不消耗燃料物品、不发熔炉经验，没有原生漏斗输入。产物按完整图结果掉落，允许多种产物；特殊配方子类与附属营火不自动获得执行支持。

### 原版切石机

标准 `minecraft:stonecutting` 配方支持原版切石机菜单。输入 0 是唯一主工件，原生列表供玩家选择可执行的图步骤；材料进度或配方定义变化后需要重新选择。

左右键取出完整一轮：第一堆到鼠标，其余到背包；Shift 在输入和容量允许时逐轮加工。关闭菜单时输入按原版行为返回，预览不会作为产物掉落。没有物品库存方块实体或漏斗加工路径；其他菜单与自定义配方子类不自动继承该适配。

### 原版锻造台

支持确切标准 `minecraft:smithing_transform`，使用完整原生 JSON 或配方引用。主工件是中间的基底，不是左侧模板：

| 逻辑输入 | 原生槽位 | 作用 |
|---|---|---|
| 0 | 中间，物理槽 1 | 主工件／基底 |
| 1 | 左侧，物理槽 0 | 模板，可声明为辅助工件 |
| 2 | 右侧，物理槽 2 | 附加材料，可声明为辅助工件 |

每轮三格各消耗一件。辅助工件分别校验图与路线，产物只继承主工件进度；原生 `result` 是解码模板，不额外发放升级结果。左右键领取完整一轮，第一堆到鼠标，其余到背包；Shift 按输入和容量逐轮加工。关闭菜单按原版返还输入，不掉落预览。

标准 `minecraft:smithing_trim` 也可执行图步骤：保留原生基底条件，合法纹饰后的盔甲及原生组件承载主工件的新进度；已有相同图案和材质时不消耗、不推进。图默认中间物品不替换盔甲，纹饰节点不得设置 `transitional_item`；finish 按图产物结算。

普通锻造保持原生行为；其他动态配方、特殊子类及附属菜单不因此获得支持。

### Create 的原版替代设备

不必把同一道工序重写成 Create 配方。设备按原生条件接纳以下标准原版图节点，不向全局配方表复制注册：

| 原版来源 | Create 设备 | 接纳条件 |
|---|---|---|
| 标准无序合成 | 搅拌器＋工作盆 | 开关开启；材料数大于 1；不是当前可压缩配方 |
| 4 或 9 个等价材料的标准合成 | 动力冲压机＋工作盆 | 开关开启；按原始材料调用上游 `canCompress` 判定，再替换图主工件 |
| `minecraft:stonecutting` | 动力锯 | 开关开启；输出过滤仍生效，按当前图工件／产物而非模板产物筛选 |
| 标准有序／无序合成 | 机械合成器 | 开关开启；保留网格匹配、主辅工件绑定与原生出料 |
| `minecraft:smoking` | 鼓风烟熏 | 原生介质与处理计时 |
| `minecraft:smelting`，否则 `minecraft:blasting` | 鼓风熔炼 | 熔炼优先；保留原生介质、计时及食品判定 |

各设备沿用上游自动化排除规则；引用配方使用原 ID 判断，内联节点使用图 ID。机械合成器输出完整图结果及原生容器返还物，不额外发放模板产物。

鼓风每次处理只推进当前步骤；换件或重载不会借用旧任务倒计时，完成产物保留同次处理锁。若同一原料的烟熏配方与熔炼配方产物相同，仍按 Create 的食品规则判定；已有图进度的工件不会回退普通烧毁处理。`campfire_cooking` 不是烟熏来源。

此接入不包括特殊合成、药水搅拌、鼓风洗涤／缠魂或附属自定义设备。

## 保护与预览边界

- 未接入的鼓风处理类型仍只保护已有图工件，不执行图步骤。
- 通过原生 `RecipeManager` 匹配查询时，任一非空输入带图进度都会阻止普通配方回退，包括无序合成和缓存查询。背包／工作台、合成器、熔炉族、营火、切石机和锻造台的图加工另走各自的提交入口，不放开此保护。直接调用普通配方方法、独立缓存产物或绕过查询的其他设备不在这层保护内。
- 完整原生配方引用可在 JEI 展示更多模组的多输入配方；只有上述已适配设备类型才可能执行，且仍需通过角色、资源和容量校验。
- 附属配方使用受支持的 Create 原生类型时，仍可执行；附属自定义加工类型不启用图执行。通用 JEI 预览须能取得对应原生布局，并非所有类别都能显示。
- 首版不包含 CCB、Fantasizing 等附属的专用机器适配。它们的普通加工可能消耗或覆盖工件进度。

管理员可运行 `/graph_assembly compatibility` 查看发现报告和禁用节点原因。报告列出配方发现与适配状态，便于定位不能执行的节点。

### 附属读取原版配方

读取原版配方不等于复用图执行入口。如Ratatouille 烤箱通过原版查询拒绝带进度工件，但不能发现仅有图节点的烟熏步骤；Vintage Improvements 振动台的原版拆解缓存会把带进度铁块加工为 9 个普通铁锭，丢失进度。注意：该旁路尚未修复。
